# 乒乓球世界重构方案

- 状态：✅ 已实施（分支 `rebuild/react-nextjs`，实施结果见第 11 节）
- 日期：2026-11-25
- 范围：把现有的静态 HTML 站重构到 React 技术栈，重做视觉和交互，并补全内容

## 1. 目标

- 好看：有一套统一、克制的设计语言，不再是 emoji、渐变和占位图拼起来的页面
- 内容完整：每个栏目有足够的深度和准确的细节，结构上支持持续扩充
- 架构现代：React 技术栈，组件化，内容与页面分离
- 交互出色：页面转场、滚动动效、筛选、搜索等体验流畅

## 2. 现状诊断

### 2.1 工程结构

现有站点是 7 个手写 HTML 页面（index、history、rules、techniques、equipment、players、tournaments），加一个近 1200 行的 `css/styles.css` 和一个 `js/script.js`。

- 导航和页脚在每个页面里各写了一遍，改一处要改 7 个文件
- 红色和青绿两套渐变混用，图标全部使用 emoji
- 图片全部是 `placehold.co` 的外链占位图；`images/` 目录里唯一的文件 `deng-yaping.jpg` 是 0 字节
- `download-images.js` 里的 Wikimedia 图片地址，从当前开发机测试 3 个均无法连接
- 国籍使用 emoji 国旗，Windows 上不显示旗帜，只显示 `CN`、`SE` 这样的字母
- `download.html` 和几个下载脚本是一次性工具
- 远端有分支 `cloudflare/workers-autoconfig`，带 `wrangler.jsonc`，以纯静态资源方式托管在 Cloudflare Workers

### 2.2 内容

各栏目的现状规模见第 7 节，已知的内容错误见第 9 节。

## 3. 技术选型

| 层 | 选择 | 为什么 |
|---|---|---|
| 框架 | Next.js 16 + React 19 + TypeScript | 文件路由和共享布局，解决导航、页脚重复的问题；每个页面构建时生成静态 HTML，首屏快，搜索引擎能直接读到全文 |
| 部署 | 静态导出，托管在 Cloudflare Workers | 产物是纯静态文件，沿用现有的托管方式，不需要服务器；旧的 `/players.html` 链接会自动跳转到 `/players` |
| 样式 | Tailwind CSS 4 | 颜色、字号、圆角、阴影集中定义在一处，换肤和深色模式不用改组件 |
| 组件 | shadcn/ui | 目前最主流的方案之一：组件代码直接进仓库，可以随意改；配套的模板和动效组件也最多 |
| 动效 | Motion for React | 页面转场、滚动进场、筛选时的卡片重排、数字滚动、滚动驱动的时间线 |
| 图标与图表 | lucide-react、Recharts | 替换全部 emoji；画奖牌榜和历届冠军分布 |
| 内容 | TypeScript 数据文件 + Zod 校验，长文用 MDX | 内容和页面分离；引用了不存在的球员或赛事时，构建直接报错 |

补充说明：

- 没选 Vite + React Router 单页应用：它更轻，但首屏是空白壳、搜索引擎收录差，内容站不划算
- 静态导出模式下不支持中间件、重写、重定向、响应头配置和默认的图片优化，这些需求要在构建期或 Cloudflare 一侧解决
- 升级路径：以后要加评论、账号这类需要服务端的功能，在 Cloudflare 上切到 Next.js 的服务端渲染模式即可，不用换框架

版本参考（2026-11-25 当天 npm 上的最新版，开工时以实际安装为准）：Next.js 16.4.6、React 19.3.1、Tailwind CSS 4.3.5、Motion 14.14.0、shadcn CLI 4.23.0、lucide-react 1.80.0、Recharts 3.11.1、Zod 4.6.7

## 4. 架构

```
tabletennis-site/
├── content/                内容层：纯数据，不含样式
│   ├── players/ tournaments/ techniques/ rules/ equipment/ history/
│   └── schema/             Zod 类型定义
├── lib/                    读取和校验内容
├── components/
│   ├── ui/                 shadcn/ui 基础组件
│   ├── layout/             导航、页脚、面包屑
│   └── motion/             可复用的动效组件
├── app/                    路由
│   ├── layout.tsx          全局布局
│   ├── page.tsx            首页
│   ├── history/
│   ├── players/
│   │   ├── page.tsx        名录
│   │   └── [slug]/page.tsx 运动员详情
│   ├── tournaments/  techniques/  rules/  equipment/
│   ├── stats/  glossary/  about/
│   └── not-found.tsx
└── public/                 自托管的图片
```

三层职责：

- **内容层**（`content/`）：所有栏目的内容以数据文件的形式存在，纯数据，不含样式；`schema/` 里的 Zod 定义约束每个字段
- **读取层**（`lib/`）：读取并校验内容，提供带类型的数据访问函数；校验失败时构建直接报错
- **展示层**（`app/` 和 `components/`）：路由按栏目划分，每个栏目一个目录，列表页是 `page.tsx`，详情页是 `[slug]/page.tsx`

以运动员为例：加一位运动员只需在 `content/players/` 新增一个文件，名录和详情页会自动生成。

## 6. 视觉方向

走体育杂志风，把质感做在排版和留白上，而不是堆渐变和特效。

- **配色**：纸白和墨黑打底，中国红只用在按钮、高亮和数据上，球台蓝绿做辅助色，不再用大面积渐变
- **字体**：标题用大字号、紧字距的粗黑体，数据用等宽数字；正文用系统中文字体，不拖慢加载
- **动效**：快而克制（150 到 400 毫秒），只在首页进场、时间线滚动、筛选重排这几处做记忆点，并遵循系统的“减弱动态效果”设置
- **图标和图像**：全部换成矢量图标、真实照片和示意图

## 11. 实施结果（2026-11-25）

### 11.1 交付内容

- 工程骨架：Next.js 16.4.6 + React 19 + TypeScript（App Router、`output: "export"` 静态导出）、Tailwind CSS 4、shadcn/ui、Motion、Recharts、Zod
- 内容层：`content/` 目录 + Zod Schema 校验，全部栏目数据迁移并完成第 9.1 节的更正
- 页面：首页、历史、运动员名录 + 41 个详情页、赛事、技术列表 + 25 个详情页、规则、装备、数据中心、术语词典、关于、404
- 交互：Ctrl/⌘+K 全站搜索（构建期生成 `search-index.json`）、运动员多维筛选（卡片重排动画）、滚动驱动时间线、计分演示、选拍向导、深色模式、页面转场
- 验证：`next build` 通过（81 个静态页面）；本地静态服务器 + 浏览器实测了首页、名录筛选、搜索跳转、详情页与深色模式

### 11.2 与原方案的偏差

| 原方案 | 实际实施 | 原因 |
|---|---|---|
| 长文用 MDX | 历史专题等长文用结构化 TS 数据承载 | 静态导出下省去 MDX 构建链，内容仍与页面分离 |
| 新增选手"在 content/players/ 新增一个文件" | 按分组文件追加记录（中国男/女、国际） | 减少文件数量，添加方式同样简单 |
| 内容补全"扩到 40 人左右" | 41 人 | — |
